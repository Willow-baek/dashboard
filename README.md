# 우리 집 대시보드

GitHub Pages에서 동작하는 정적 일정 화면. 기존의 날씨별 배경·애니메이션, 반투명 박스, 큰 날짜·디지털 시계, 한마디, 가로 일정 행 디자인을 유지합니다. `index.html`을 열거나 정적 HTTP 서버로 미리 볼 수 있습니다. 빌드 과정은 없습니다.

## 화면

- 하단 기록 버튼 제거. 넓어진 기존 일정 박스 안에서 오늘 / 이번 주 / 앞으로 4주 / 예약 확인으로 일정 구분.
- 오늘은 빨강, 이번 주는 파랑으로 구분하며 같은 가로 행 배치를 사용합니다. 기본 목록은 반복 일정마다 가장 가까운 회차 하나만 표시합니다. 예정 시간이 지나면 다음 회차로 넘어가고, 미확정 시간은 그 날짜가 끝날 때 넘어갑니다. 실제 방문 완료를 의미하지 않습니다. 주간·월간 달력에는 모든 회차가 계속 표시됩니다.
- 상단 날짜줄: 주간 펼침 → 월간 → 접힘. 주간은 날짜줄 아래에 내용 높이만큼 펼쳐져 시계/한마디/일정을 아래로 밀며, 일정이 많으면 주간 박스 안에서 스크롤합니다. 월간은 기존처럼 큰 달력 화면을 사용합니다. 개별 날짜와 일정을 눌러 상세 확인.
- 빈 `quote`는 외출 시간대 날씨 코멘트로 대체. `quote_date`가 있으면 그 날짜에만 직접 쓴 한마디 표시.
- 시설 안내는 접힌 작은 메뉴. 각 시설을 누르면 요일별 운영시간과 현재 상태를 확인합니다. 헬스장은 지운이의 회원권 일시 중지와 시설 운영시간을 구분합니다. 옥상은 폐쇄 안내가 운영시간보다 우선합니다. 시간표는 원래 대시보드에서 복원한 안내이며 실시간 운영 조회가 아닙니다.
- 한마디와 오늘 일정의 중복 제목을 숨겨 일정 공간을 확보합니다. 소리/새로고침 버튼은 하단에 있습니다. 마지막 일정은 기기에 저장하며, 연결 실패 시 새로고침 아이콘이 경고색으로 바뀝니다. 갱신 시각은 버튼 툴팁과 접근성 상태에 남습니다.
- ‘알림’을 체크한 일정은 1시간·30분·15분·10분·5분 전에 화면·한국어 음성으로 안내합니다. 준비·이동시간이 비어 있으면 일정 시작 시각 기준이고, 값이 있으면 그 분만큼 앞당긴 준비·출발 시각 기준으로 안내하며 해당 시각에도 한 번 알려줍니다. 예: 오후 2시 일정에 40분이면 오후 1:20 기준입니다. 10초 간격으로 확인하며 각 단계는 한 번만 나옵니다. 늦게 열면 놓친 단계들을 연속 재생하지 않습니다. 준비·출발 시각 안내는 최대 5분 이내의 지연만 보완하며 일정 시작 이후에는 울리지 않습니다. 모든 음성은 ‘지운아’로 시작합니다. 전체 음성 기본값은 켜짐이고 기기별 켜짐/꺼짐 설정을 저장해 복원합니다. 브라우저 자동 재생 제한은 설정 저장으로 해제되지 않으며 활성화 스피커 또는 화면 클릭/키 입력으로 아직 유효한 알림을 다시 읽습니다. 미지원/기타 오류 시 차임벨로 대체합니다. 닫힌 화면, 잠금 또는 정지된 브라우저의 백그라운드 알림은 보장하지 않습니다.

## 오늘 일정 브리핑과 누나 컴백

오늘 일정을 클릭하면 기존 상세 팝업을 유지하면서 오늘 일정 전체를 시간순으로 읽고, 선택한 일정까지 남은 시간과 준비·출발 시각을 안내합니다. 하단 **오늘 일정 브리핑** 버튼(`id="today-briefing"`)은 오늘 전체를 읽고 다음 일정까지 남은 시간을 알려줍니다. 동생 PC의 자동 클릭에는 이 버튼 하나를 사용하면 됩니다. 클릭하는 순간의 한국 시간을 기준으로 계산하며, 팝업의 남은 시간은 열려 있는 동안 갱신하지만 음성은 클릭할 때만 나옵니다. 여러 번 클릭하면 이전 브리핑을 멈추고 새로 읽습니다. 취소된 일정은 제외하고, 예정 시간이 지난 일정은 완료했다고 추정하지 않습니다. 미확정 시간과 연결 실패/오래된 저장 데이터는 별도로 안내합니다. 다른 날짜 일정 클릭은 기존 상세 확인만 유지합니다.

음성 끄기 설정을 존중합니다. 팝업에서 **음성 켜고 브리핑 듣기**를 누르면 켜고 읽을 수 있습니다. 브라우저 자동 재생 정책과 기기 음량 때문에 실제 동생 PC에서 한 번 클릭해 소리를 확인해야 합니다. PC 잠금·절전·종료 상태의 자동 클릭은 보장하지 않습니다. 이 사이트 자체가 PC의 예약 작업을 생성하지는 않습니다.

`2026-11-10`부터 한마디 공간에 **누나 컴백 D-N**과 멘트를 표시합니다. 귀국 예정일은 `2027-11-12`이며 한국 날짜가 바뀌면 카운트를 갱신합니다. `2026-11-10 = D-367`, `11-11 = D-366`, `11-12 = D-365`, 귀국일은 `D-DAY`, 이후에는 `D+N`입니다. 카운트다운은 기존 한마디보다 우선 표시합니다.

기본값은 `config.js`의 `returnCountdown`에 있습니다. 연결 시트 `시트1`에 `return_date`, `return_start`, `return_message` 키가 있으면 각각 귀국 예정일·표시 시작일·멘트를 덮어씁니다. 예전 `quote`는 출국 이후 카운트다운을 덮지 않습니다. 멘트는 공개 대시보드에 표시되므로 공개해도 되는 내용만 입력합니다.

## 결제 알림과 공유 기록

일정 상단의 **결제할 것**에 새 묶음 결제 7일 전부터 짧은 버튼을 표시합니다. 3일 전부터 D-day 숫자가 천천히 깜빡이고, 움직임 줄이기 설정에서는 고정 표시합니다. 기한 당일은 D-DAY, 미확인 상태로 기한이 지나면 경과일을 표시합니다. 취소된 회차는 횟수에서 제외하므로 결제 기준일도 실제 예정 회차에 맞춰 바뀝니다. 결제 완료는 자동 추정하지 않습니다.

버튼은 결제 기한·방법·금액을 보여주고 **오늘 결제했어요**를 누르면 오늘 결제일과 다음 묶음의 첫 회차를 저장합니다. 실제 카드 청구를 수행하지 않습니다. 코나는 상담 갈 때 카드를 지참하고, 와이랩은 수업 전에 방문해서 결제하는 안내를 사용합니다. `config.js`의 `payments.instructions`에서 안내와 알려진 금액을 변경할 수 있습니다.

모든 기기 공유를 위해 `apps-script/Payments.gs`를 **본인 계정 소유의 별도 Apps Script 프로젝트**에 저장합니다. `initializePayments`를 실행하면 대상 일정표 ID를 고정하고 무작위 가족 연결 코드를 만들며, 상세 결제 이력용 비공개 스프레드시트를 따로 만듭니다. 금액·결제방법은 이 비공개 이력에 저장하며 공개 일정표에는 기존 묶음 시작일·결제일 두 칸만 갱신합니다. 새 웹 앱으로 배포한 뒤 URL을 `config.js`의 `payments.endpoint`에 설정합니다. 가족 연결 코드는 공개 코드에 넣지 않고 각 기기의 **결제기록 연결** 화면에 한 번 입력합니다. 코드가 없거나 틀린 요청은 읽기·쓰기 모두 거부합니다. 같은 확인 요청과 같은 묶음의 중복 클릭은 한 건으로 처리합니다. 연결이 없거나 저장에 실패하면 완료 처리하지 않습니다.

Google 승인이 필요한 권한은 스프레드시트 읽기·쓰기·생성입니다. 코드는 고정된 대시보드와 생성한 비공개 결제이력 파일만 사용하며 다른 파일 ID를 요청 본문에서 받지 않습니다. 이 권한 승인과 웹 앱 배포는 사용자가 검토한 뒤 진행합니다. 연결된 다른 기기는 매분 최신 결제 상태를 확인합니다. 시트에서 더 최신 묶음으로 직접 수정한 경우 오래된 응답으로 되돌리지 않습니다.

## PC를 켜둔 상태의 백그라운드 알림

**PC 알림 준비**에서 음성 테스트와 선택적인 시스템 알림 권한을 설정합니다. Windows에서 대시보드를 최소화하거나 다른 탭을 사용하더라도 페이지가 실행 중이면 기존 준비·출발/시작 알림을 시도합니다. 음성은 브라우저의 사용자 활성화와 기기 음량에 영향을 받습니다. 시스템 알림은 사이트 권한 허용과 Windows 방해 금지 설정에 영향을 받으며, 브라우저가 닫힌 상태에 서버 푸시를 보내는 기능은 아닙니다.

Chrome의 설정 → 성능 → 항상 활성 상태로 유지할 사이트에 `willow-baek.github.io`를 추가하고 탭을 고정하세요. 탭이 비활성화되거나 PC가 절전·종료된 경우 웹 타이머만으로 알림을 보장하지 않습니다. 브라우저가 백그라운드 타이머를 늦추면 실제 남은 시간을 기준으로 현재 유효한 단계 하나만 안내합니다. 놓친 단계 전체를 몰아서 읽지 않고, 준비·출발 보완은 기존 5분 범위까지만 적용합니다. 페이지 복귀·온라인 복구·페이지 복원 때 최신 일정을 다시 읽습니다. 같은 프로필의 여러 탭은 Web Locks와 공유 저장된 알림 이력으로 중복 전달을 막고, 잠금 기능 미지원 환경은 저장 이력 확인으로 보완합니다.

## 기존 시트 사용

`시트1`의 `key`, `value` 구조를 그대로 읽습니다. `eventN_date`, `eventN_time`, `eventN_title`, `eventN_repeat`, `eventN_contact`, `eventN_memo`를 유지하며 N은 10개로 제한하지 않습니다.

추가할 수 있는 키:

| key | value 예시 | 의미 |
| --- | --- | --- |
| quote | 오늘 우산 챙겨가 | 직접 쓴 한마디. 빈 값이면 자동 날씨 |
| quote_date | 2026-10-13 | 선택. 비우면 지울 때까지 유지 |
| author | 누나 | 선택. 한마디 작성자 |
| event1_time_mode | 매회 확인 | 기준 날짜만 입력된 시간을 사용. 다음 회차는 미확정 |
| event1_travel_minutes | 40 | 준비와 이동을 합한 분. 비우면 시작 시간 기준 알림 |
| event1_end_date | 2026-12-31 | 반복 종료일. 비우면 계속 반복 |
| event1_active | 중단 | 이 일정을 숨기고 반복 중단 |
| gym_status | 지운이 회원권 일시 중지 | 개인 회원권 안내. 시설 운영 상태와 구분 |
| gym_facility_status | 임시 휴무 | 선택. 헬스장 시설의 별도 운영 안내 |
| roof_status | 폐쇄 | 시설 안내 |
| library_hours | 운영시간 확인 필요 | 기본값이면 기존 요일별 시간표 사용. 다른 값을 입력하면 별도 시간 안내로 표시하며 운영 여부는 추정하지 않음 |
| library_status | 임시 휴관 | 선택. 도서관의 별도 현재 상태 안내 |

현재 시트의 성모드림(`event1`)은 사용자의 설명에 따라 `config.js`에서 기본 시간 방식을 `매회 확인`으로 지정했습니다. 시트에서 `event1_time_mode=고정`을 지정하면 덮어씁니다. ID를 재사용하면 이 설정도 변경하세요. 코나/와이랩은 기존 입력 시간을 반복합니다. 반복은 `1주마다`, `2주마다`, `매주`, `격주` 등을 지원하고 날짜는 기준 회차입니다. 무한 반복이 아닌 수업이면 종료일을 입력하세요.

기존 시트에서도 아래처럼 예외를 추가할 수 있습니다. 하나의 예외가 한 회차만 변경합니다.

```text
exception1_event_id       event1
exception1_original_date  2026-11-03
exception1_action         시간 확정
exception1_time           10:30
```

이동: `action=변경`, `exception1_date=변경 날짜`, `exception1_time=변경 시간`. 취소: `action=취소`. `memo`도 가능. 한 ID/원래 날짜 조합에는 한 예외만 입력하세요. 예외를 지우면 원래 반복으로 돌아옵니다.

## 한 행에 한 일정으로 전환

현재 연결 시트는 `일정`, `변경사항`, `사용안내` 탭으로 전환했습니다. `일정`의 빈 행에 이름·기준날짜·시간을 입력하면 새 일정이 추가됩니다. 번호나 ID를 복사할 필요가 없습니다. 반복과 시간방식은 드롭다운이며, `중단` 체크박스를 선택하면 숨겨집니다. 기존 6개 일정의 ID는 숨김 열에 보존했습니다. 새 일정은 이름으로 자동 식별하므로 이름을 서로 구분하고, 이름을 바꾸면 관련 변경사항의 일정 이름도 함께 바꾸세요.

다른 시트에 이 앱을 연결할 때는 다음 순서로 전환합니다.

1. 같은 스프레드시트에 `일정` 탭을 만들고 `sheet-templates/일정.csv`를 가져옵니다. 실제 방문일·시간·종료일을 확인합니다.
2. `변경사항` 탭을 만들고 `sheet-templates/변경사항.csv`의 헤더만 가져옵니다. 예시는 별도의 `변경사항-예시.csv`입니다. 예시를 실제 변경으로 적용하지 마세요.
3. 두 탭도 현재 시트와 같은 읽기 권한으로 노출되어야 합니다. 앱이 사용하는 opensheet에서 읽히는지 확인합니다.
4. 기존 `시트1`에 `schedule_tab=일정`, `exceptions_tab=변경사항`을 추가합니다. 그때부터 새 탭을 사용합니다.
5. 기존 event 키는 백업으로 남겨도 됩니다. 한마디와 시설 키는 계속 `시트1`에서 읽습니다.

현재 `일정` 헤더: `날짜,시간,일정,기간종료일,알림,반복,시간방식,준비·이동시간,연락처,메모,반복종료일,중단,일정ID,묶음횟수,결제묶음시작일,결제일`.
`알림`은 일정 이름 옆 체크박스입니다. 기존 아카데미/방문/오는 날 일정은 해제하고 나머지는 체크했습니다. 새 일정은 알림이 필요하면 체크하세요. 해제해도 일정과 수업 회차는 계속 표시됩니다. 체크박스 값이 이름에 따른 기본값보다 우선하므로 아카데미도 체크하면 알림이 나옵니다. 기존 형식에서는 `eventN_alerts=TRUE/FALSE`를 사용할 수 있습니다.
현재 `변경사항` 헤더: `일정,원래날짜,처리,변경날짜,변경시간,메모`. 일정 이름을 고르고 날짜와 처리 방식을 입력합니다.
기존 CSV의 영문 헤더와 ID 기반 변경사항도 계속 지원합니다. `시간방식=매회 확인`이면 각 미래 회차에 `시간 확정` 예외를 입력합니다. 기준날짜를 비운 일정은 예약 확인에 표시됩니다. 준비·이동시간은 임의로 추정하지 않으므로 직접 입력하세요.

새 탭 하나라도 읽기 실패하면 이번 갱신 전체를 보류하고 마지막 정상 데이터를 유지합니다. 잘못된 날짜/반복은 예약 확인에 표시됩니다. 잘못된 시간은 시간 확인 필요로 표시하고 알림을 울리지 않습니다.

## 기간 일정

하루짜리 일정은 기존처럼 날짜·시간·이름만 입력합니다. 여행·방문처럼 며칠 이어지는 일정이면 `기간종료일`에 끝나는 날짜 하나만 추가합니다. 날짜는 시작일, 시간은 선택적인 시작/출발 시각입니다. 반복은 없음 또는 빈 값으로 둡니다. 별도의 일정 종류나 참석자 입력은 필요하지 않습니다.

기본 목록은 한 줄만 유지하고 시작 이후에는 `진행 중`과 `끝나는 날까지`를 표시합니다. 날짜는 `10/23(금)-25(일)`처럼 요일을 넣고 같은 달의 월 중복만 생략합니다. 달/연도가 바뀌면 필요한 월/연도를 표시합니다. 기간 종료일 당일 자정까지 보이며 다음 날 사라집니다. 주간·월간 달력에는 겹치는 모든 날짜에 표시합니다. 알림은 시작 전의 한 번의 준비·출발 또는 시작 시각을 기준으로 나가고 매일 반복하지 않습니다. 시간이 없으면 음성 알림은 없습니다. 귀가 알림이 필요하면 별도의 일정 한 줄을 추가하세요.

`반복종료일`은 매주·격주 수업 같은 반복 자체를 멈추는 날짜이며 `기간종료일`과 별개입니다. 종료일이 시작일보다 빠르거나 형식이 잘못되면 확인 대상으로 표시합니다. 변경사항에서 시작일을 옮기면 기간 길이도 그대로 옮겨지고 취소하면 전체 기간이 취소됩니다. 기존 영문 입력에서는 `period_end`, 예전 형식에서는 `eventN_period_end`를 사용할 수 있습니다.

## 수업 묶음과 결제

와이랩은 `묶음횟수=4`, `결제묶음시작일=2026-10-04`, `결제일=2026-09-30`입니다. 예정 수업을 세어 제목에 회차를 표시합니다. 취소는 차감하지 않으며 날짜를 변경한 수업은 변경된 날짜 순서에서 한 번만 셉니다. 출석 완료를 확인하는 기능은 아닙니다.

취소/변경이 없다면 10/18=3/4, 10/25=4/4, 11/1=다음 묶음 1/4입니다. 마지막 수업 행에 다음 묶음 시작일과 결제 안내를 표시하고, 새 묶음은 결제 확인 필요로 표시합니다. 실제 다음 결제 후 `결제일`과 `결제묶음시작일`을 함께 갱신하세요. 다음 결제나 출석을 자동으로 확인하지 않습니다. 묶음 기능이 필요 없는 일정은 이 세 칸을 비워둡니다.

## 날씨와 기기

서교동 Open-Meteo 예보를 사용합니다. 지나간 시간대의 비 확률은 제외하고, 다음 8시간 중 오늘 출발 전후 2시간을 우선 확인합니다. 체감온도와 바람을 함께 판단하며 예보이므로 실제 날씨와 다를 수 있습니다. 비·추위·더위뿐 아니라 선선하거나 온화한 날에도 옷차림 조언을 표시합니다. 시간대 예보가 없으면 유효한 현재 체감온도를 사용합니다. 데이터 실패/오래된 데이터에서는 날씨 확인 필요를 표시하고 비나 추위에 대한 조건부 준비 안내를 제공합니다.

날짜·시간·알림은 기기의 시간대와 관계없이 한국 시간을 사용합니다. 구형 Safari를 고려해 정적 스크립트, 일반 Grid/Flex 레이아웃, AbortController 대체 처리를 사용합니다. 실제 구형 iPad Safari의 화면/소리/장시간 유지 동작은 별도 기기 확인이 필요합니다. 충전 중이어도 기기 잠금이나 브라우저 중단 시 알림을 보장할 수 없습니다.

```sh
node --test tests/schedule.test.cjs

```

반복 엔진은 vendored RRule, 아이콘은 vendored Lucide를 사용합니다. 각 라이선스는 `vendor/`에 있습니다. Google Sheets의 실제 데이터나 공개 사이트에는 로컬 수정만으로 변경이 생기지 않습니다. 검토 후 저장소에 커밋/푸시하면 GitHub Pages에 반영됩니다.

오늘의 한마디는 귀국 D-day 뒤에 한 줄로 표시됩니다. 유효한 quote가 있으면 기본 귀국 멘트 대신 표시하고, 비어 있으면 기본 멘트를 사용합니다. 화면 너비보다 긴 문구만 천천히 좌우로 이동하며 마우스를 올리거나 키보드로 포커스하면 멈춥니다. 동작 줄이기 설정에서는 직접 좌우 스크롤할 수 있습니다.

## 음성과 지운이 PC 전달

하단 `지운용 프롬프트`는 `handoff.js`의 최신 작업 지시를 보여주고 복사합니다. 업데이트할 때 실제로 필요한 PC 작업만 이 파일에 반영합니다. 오전 8시 앱 열기 자동화는 이미 사용자가 설정했으며 중복 생성하지 않습니다. 음성·1분 뒤 최소화 테스트 도구는 프롬프트 창의 보조 버튼으로 이동했습니다.

Google Cloud TTS는 `cloud-voice.js`와 `apps-script/Tts.gs`를 사용합니다. Apps Script Code.gs에는 Payments.gs 뒤에 Tts.gs를 함께 저장하며 기존 웹 앱 배포를 새 버전으로 업데이트합니다. 비공개 ScriptProperties에 TTS_API_KEY와 TTS_ENABLED=true를 설정하고 검증한 뒤 config.voice.enabled=true로 전환합니다. 공개 저장소나 프롬프트에 인증키를 넣지 않습니다. 현재 비공개 서버 연결과 실제 MP3 생성을 검증해 Cloud 음성을 활성화했습니다.

서버는 가족 코드를 인증하고 한국어 Neural2-A만 요청합니다. 최대 800 UTF-16 코드 단위씩 요청하며, 모든 기기를 합산해 월 50,000자를 넘기기 전에 중단합니다(미국 태평양 시간 월 기준). 불확실한 실패도 사용량에 포함하며 클라이언트는 한도나 음성 모델을 바꿀 수 없습니다. 한도를 자동으로 높이지 않습니다. 한도 도달 후 화면으로 누나에게 요청하도록 알립니다. 이 제한은 이 앱의 요청에만 적용되며 다른 앱의 Google Cloud 비용을 제어하지 않습니다. 사용자는 90일 무료 체험 계정을 만들었으며 유료 계정 업그레이드는 별도 사용자 결정입니다.

## 고양이 결제 알림

별도 제목 대신 대비를 높인 결제 버튼을 표시합니다. 생성한 투명 고양이 에셋이 버튼을 짧게 밀고 쉬며 속도와 이동 폭을 바꿉니다. 마우스·키보드 포커스·팝업·비활성 페이지에서 멈추며, 동작 줄이기 설정과 `잠깐 쉬기`를 지원합니다. 실제 결제 기록 없이 미리보기를 위해 일정을 변경하지 않습니다.
